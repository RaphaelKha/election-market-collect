# השווקים סביב הבחירות בישראל 2026

המאגר הזה מכיל את הקוד שבעזרתו אני **עוקב אחרי השווקים הפיננסיים סביב הבחירות לכנסת ה-26, ב-27 באוקטובר 2026**. למחקר שני חלקים:

1. **תגובת השווקים לבחירות.** אני עוקב אחרי השקל, הבורסה לניירות ערך בתל אביב, חברות ישראליות הנסחרות בניו יורק ושווקי חיזוי, בזמן שהתוצאות מתפרסמות.
2. **פער המחירים בין תל אביב לניו יורק.** כמה חברות ישראליות נסחרות בשתי הבורסות (רישום כפול). לאחר המרה לדולרים, המחיר בשתיהן אמור להיות זהה. אני מודד, דקה אחר דקה, כמה המחירים מתרחקים זה מזה וכמה זמן הפער נמשך, כדי לבדוק אם נשאר מקום לארביטראז' אחרי עלויות המסחר.

זהו **פרויקט אישי של תצפית ומחקר**. הקוד אינו מבצע פקודות מסחר, ואין באמור כאן ייעוץ השקעות.

> ה-README הזה פורסם לפני המדגמים (27.10.2026, ‏20:00 UTC), בכוונה: הוא מציג את השאלות לפני שהתשובות ידועות.

## חלק 2: פער המחירים תל אביב / ניו יורק (`parity_track.py`)

### השיטה

מניית טבע שנקנתה בתל אביב ומניית טבע שנקנתה בניו יורק הן אותו נייר ערך, ולכן המחיר הדולרי שלהן אמור להיות זהה. בכל דקה שבה **המניה אכן נסחרה בשתי הבורסות**:

</div>

```
TASE price in USD = (TASE price in agorot / 100) / USDILS × ratio
gap (basis points) = (New York price / TASE price in USD − 1) × 10,000
```

<div dir="rtl">

נקודת בסיס (bp) שווה ל-0.01%.

פער קטן ויציב הוא תקין (עמלות, מיסוי, הכיוון הרגיל של זרימות הכסף). מה שחשוב הוא **הסטייה מהפער הרגיל**: הפער הנוכחי פחות החציון שלו ב-300 הדקות המשותפות הקודמות.

**אפיזודה** היא רצף של דקות עוקבות שבהן הסטייה נשארת מעבר לסף, באותו כיוון. נבדקים שלושה ספים, 20, 40 ו-60 נקודות בסיס, המייצגים רמות שונות של עלויות מסחר הלוך-חזור. נספרות רק אפיזודות שנמשכות **לפחות 3 דקות**, כי אפיזודות קצרות יותר אינן משאירות זמן לבצע את שתי העסקאות.

### הצמדים

| ניו יורק | תל אביב | יחס |
|---|---|---|
| TEVA | TEVA.TA | ‏1:1 (מניות רגילות בשתי הבורסות מאז 14.9.2026) |
| NICE | NICE.TA | ‏1:1 (לבדיקה חוזרת מול דוח 20-F האחרון) |
| ESLT | ESLT.TA | ‏1:1 (טעון אימות) |
| ICL | ICL.TA | ‏1:1 (טעון אימות) |

צ'ק פוינט (CHKP) אינה נסחרת בתל אביב, ולכן אינה כלולה בחלק הזה.

### חלון המסחר המשותף

שתי הבורסות פתוחות במקביל רק לזמן קצר בכל יום:
- כ**שעה** (13:30–14:30 UTC) עד 23.10;
- כ**שעתיים** (13:30–15:30 UTC) מאז המעבר של ישראל לשעון חורף ב-25.10;
- שוב כשעה החל מ-1.11, כשארה"ב עוברת לשעון חורף.

ביום שישי המסחר בתל אביב מסתיים לפני הפתיחה בניו יורק, ולכן אין חלון משותף.

המעקב התחיל ב-5.10.2026 ורץ **מיום שני עד יום שישי ב-21:30 UTC**, אחרי הסגירה בארה"ב, וימשיך **גם אחרי 31.10**.

### מגבלות

- הפערים מחושבים לפי **מחיר העסקה האחרונה** בכל דקה, ולא לפי הצעות הקנייה והמכירה. חלק מהפערים של דקה אחת נובעים רק מקפיצת העסקאות בין מחיר הקנייה למחיר המכירה, ולכן הספירות הן **חסם עליון**.
- שער החליפין הוא ציטוט הדולר/שקל של Yahoo, ואין זה בהכרח שער שאפשר לבצע בו עסקה.
- כמה מהיחסים עדיין טעונים אימות (ראו טבלת הצמדים).
- נתוני Yahoo Finance אינם רשמיים ועלולים להכיל חורים.

1. איך הגיבו השקל, בורסת תל אביב, המניות הישראליות בניו יורק והאג"ח הממשלתיות סביב 20:00 UTC ב-27.10?

4. האם פער המחירים תל אביב / ניו יורק מתרחב סביב הבחירות, והאם הוא נשאר אי פעם רחב מספיק, ולמשך זמן מספיק, כדי לכסות את עלויות המסחר?
5. איך התגובה הזאת משתווה לזו של מערכות בחירות קודמות לכנסת?

## התקנה

נבדק עם Python 3.12.

</div>

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

.venv/bin/python status.py                    # collection status
.venv/bin/python parity_track.py              # Tel Aviv / New York gap (fetches the last 5 days)
.venv/bin/python parity_track.py --no-fetch   # recompute from data already on disk
```

<div dir="rtl">

המשימות המתוזמנות רצות עם `cron` על שרת לינוקס המוגדר לשעון UTC. עם הדגל `--cron`, סקריפטי האיסוף אינם עושים דבר אחרי התאריך `collect_until` שב-`config.yaml`.
